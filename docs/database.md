# Database design

Phase 2 establishes the initial PostgreSQL schema through SQLAlchemy 2 and Alembic.

## Ownership

Every directly user-owned table has a non-null, indexed `user_id` foreign key. Repository reads for
owned resources require both the resource identifier and the authenticated user's identifier. Join
tables connect records that have already passed ownership checks.

## Identifiers and timestamps

- Primary identifiers are UUIDs generated by the application.
- Stored timestamps use timezone-aware columns and UTC application defaults.
- User timezones are stored as IANA timezone names and conversion belongs at API/UI boundaries.
- Models use `created_at` and `updated_at` where record history is meaningful.

## Lifecycle fields

Posts, campaigns, schedules, publishing attempts, AI jobs, templates, and content ideas use explicit
enum states rather than overlapping boolean flags. State-transition rules are added in the service
phase for each feature.

## Migrations

The schema is changed only through Alembic revisions. From `backend/`:

```powershell
uv run alembic upgrade head
uv run alembic downgrade -1
uv run alembic revision --autogenerate -m "describe the change"
```

Always inspect autogenerated revisions and test both upgrade and downgrade paths before committing.
